# 右侧操作栏重排设计（阶段分组 + 折叠）

## 一、目标与概述

随着功能增长，右侧参数面板演化为 15 段连续长滚动列表，用户反馈"功能喜欢但不好用"。
本次重排**只改布局组织与展示时机，不改任何功能逻辑、数据流与后端接口**，解决三个核心问题：

1. **导入入口分散**：`导入 docx`（正文文本）藏在文本对齐按钮行；`文档底图-导入`（打印底图，
   弹窗二选一：识别高亮填空 / 纯底图）；`背景-选择`（图片）；`预设-载入`——四种"导入文件"
   意图散落在三处以上，且语义不易区分。
2. **无关功能混排**：主题切换与「关于/检查更新」按钮挤在「待处理文本」标题行（底部状态栏
   已有同名"关于与更新"入口，构成重复）；角色标记条、区域列表等"混排高级流"与"粘贴文本即导出"
   的简单流交叉出现。
3. **低频高级参数永远占屏**：笔画扰动、写错字、边距、随机扰动列等"调一次就不管"的参数默认
   全部展开，把高频操作（文本编辑、导入、导出）挤出首屏。

技术栈现状：Tauri 2 + Vue 3 + Naive UI；右栏为 `src/components/ParamsPanel.vue`（单文件模板），
内嵌 `ParaEditor` / `RegionList` / `RoleManager` 组件与 `RegionDialog`。

## 二、分组结构（单列，6 组，按使用阶段排序）

| 组 | 折叠头文案 | 默认状态 | 内容（全部为现有控件原样搬移） |
|---|---|---|---|
| ① | 文本内容 | 展开 | 对齐/缩进工具行（左/中/右/首行缩进/取消缩进）、选区角色标记条、段落状态提示行、`ParaEditor` |
| ② | 文字区域（N） | `store.regions.length > 0` 时展开，否则折叠 | `RegionList` 全部内容（含删除选中/清空） |
| ③ | 笔迹角色（N） | 折叠 | `RoleManager` 整卡（含角色卡片内部展开逻辑，不受影响） |
| ④ | 导入素材 | 展开 | 统一导入入口 + 素材选择（见下节） |
| ⑤ | 笔迹仿真与版式 | 折叠 | 排版参数、笔画扰动、写错字、边距（含边界提示）、文字颜色 |
| ⑥ | 预设 | 折叠 | 预设下拉 + 载入 + 保存 |

首屏效果：区域为空时仅见 ①+④，文本编辑器占据大部分高度；调参用户展开 ⑤ 后由状态记忆保持。

## 三、④ 导入素材组内部布局

自上而下（每项为按钮/控件 + 一句话说明，消除语义歧义）：

1. **导入 Word 正文文本 (.docx)** —— 按钮调用现有 `importDocx()`；说明：「导入为待处理文本，
   保留高亮/角色标记」。（从对齐按钮行移除原「导入 docx」）
2. **导入 PDF/Word 打印底图** —— 按钮调用现有 `importDocument()`；说明：「逐页作为背景，
   可选识别高亮填空」；保留现有 `askDocumentImportMode()` 二选一弹窗与 `docStatus` 只读
   状态展示（压缩为一行状态文本 + 重新导入按钮）。
3. **背景图片** —— 现有 `backgroundPath` 输入框 + `chooseBackground()` 选择按钮。
4. **字体** —— 现有 `FontPicker`。

文字颜色、边距等外观参数归入 ⑤（它们是"效果参数"而非"素材文件"）。

## 四、关键决策与理由

1. **折叠头带计数**：`文字区域（3）`、`笔迹角色（4）`——折叠时仍可见状态，降低"藏功能"焦虑。
2. **展开状态持久化**：6 组各自的展开/折叠状态写入 `localStorage`（键名
   `handwrite_panel_collapse`，JSON），重启后保持用户上次的选择；首次使用按第二节默认值。
3. **编辑态组件不卸载**：①②③ 组使用 Naive UI `NCollapseItem` 的 `display-directive="show"`
   （默认 `if` 会卸载隐藏内容）：① 保住 `ParaEditor` 的焦点、选区、滚动位置；② 保住
   `RegionList` 悬浮高亮索引；③ 保住 `RoleManager` 角色卡的内部展开态。④⑤⑥ 组内无
   需要保活的编辑态控件，可用默认 `if`（折叠时卸载，减少常驻 DOM）。
4. **去重**：删除「待处理文本」标题行的 ℹ️ 关于/检查更新按钮（底部状态栏已有
   「v{版本} · 关于与更新」）；主题切换按钮（🖥️/☀️/🌙 三态）移至底部状态栏
   「使用教程」左侧，行为不变（`cycleThemePreference` / `setThemePreference`）。
5. **选区角色条按需显示**（本次纳入范围的增强）：选区角色标记条仅当编辑器存在文本选区时
   显示。判定依据 `ParaEditor` 上报的选区状态（现有 `getSelectedParaIds()` 已有选区跟踪，
   需暴露一个响应式 `hasSelection`）；无选区时整条隐藏，避免无效点击。若实现中发现选区
   状态追踪成本超预期，可降级为"常显但无选区时置灰"，功能语义不变。
6. **② ③ 组提示文案精简**：`RegionList` 现有三行提示（操作说明 ×2 + 角色联动提示）压缩为
   一行折叠头下方的小字说明；完整操作教程仍由底部「使用教程」承载。

## 五、不动的部分

- 左栏预览工具栏（上一页/下一页/预览底色/框选文字）与预览交互。
- 底部主按钮行（预览/导出/导出 PDF）位置与行为。
- `RegionDialog`、`HelpModal`、`AboutModal`、`UpdateModal` 及所有弹窗逻辑。
- `store.ts` 全部业务逻辑、参数防抖渲染链路、后端 Rust 命令。

## 七、验证方式

1. `pnpm build` 通过、无类型错误。
2. 本地起页面（`pnpm dev`）逐项核对：
   - 6 组默认展开/折叠正确；② 随区域数量联动；
   - 各组展开状态刷新页面后保持（localStorage）；
   - ① 折叠再展开后编辑器焦点/选区不丢；
   - ④ 内四个导入入口全部可点且行为与改动前一致（docx 正文、底图二选一弹窗、背景、字体）；
   - 状态栏主题切换三态正常，标题行按钮已移除；
   - 选区角色条：无选区隐藏、有选区出现且标记生效；
   - 深浅两种主题下折叠头/计数样式正常。
3. 后端无改动，不涉及 Rust 测试。
